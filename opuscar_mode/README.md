# روش لِمو — مسیر مستقل تولید موشن

دو روش مستقل در این پروژه ثبت شده‌اند:

1. **روش اصلی:** دستور قبلی در `../MASTER-PROMPT-CONTENT-MOTION.md` و `../START-PROMPT.md` و راهنمای مرجع `../motion_reference/style_guide.md`.
2. **روش لِمو:** این راهنما، دستور مستقل `../motion_reference/lemo_opuscar_addendum.md` و موتور رندرِ این پوشه. در هر پروژه کاربر انتخاب می‌کند و این دو روش خودکار با هم ترکیب نمی‌شوند؛ اگر انتخاب روشن نیست پیش از تولید بپرس.

در هر دو روش ترجیحات صریح و عمومی کاربر و الزامات ایمنی `../AGENTS.md` معتبر است: فارسی درست و فونت وزیرمتن، زمان‌بندی با نریشن، تایید عنوان بعدی و نریشن و استوری‌بورد قبل از ساخت مگر خلاف آن خواسته شود، قاب‌های دایره‌ای در موشن، موسیقی ملایم، ممنوعیت عروسک سادهٔ کدنویسی‌شده و حفظ صدای تاییدشده و قانون جداگانه کاور. دستور صریح پروژه مقدم است. این موارد به معنی استفادهٔ خودکار از گردش‌کار روش دیگر نیست.

## قواعد ثابت تصویری و نریشن

در لِمو و روش اصلی، زمینهٔ اسلایدهای غیرکاور همیشه سیاه است. سبک تصویر غیرکاور به پیکسار محدود نیست و می‌تواند استاپ‌موشن یا سبک دیگری باشد. متن‌ها بسیار درشت، رنگی، درخشان و نئونی و حرکت متن و تصویر فراوان و معنادار باشند. زیرنویس جداگانه لازم نیست؛ نریشن فقط متن متحرکِ ظاهرشونده را به‌ترتیب و هماهنگ بخواند. قانون و سبک کاور، تصویر ۱۶:۹ و عنوان بیرون کادر ثابت است. جزئیات و محدودیت‌ها در `../motion_reference/lemo_opuscar_addendum.md` ثبت شده‌اند.

## درخواست ویدیو

مثال: «با روش لِمو یک موشن ۳۰ ثانیه‌ای دربارهٔ مهارت‌های کودک چهار ساله بساز؛ عمودی ۴:۵، رنگ سبز و سرخابی. اول نریشن و استوری‌بورد را برای تأیید بفرست.» برای روش قبلی بگویید «با روش اصلی ...». موضوع، مدت، ابعاد، رنگ‌ها، صدای درخواستی و هر مرجع را می‌توانید تعیین کنید؛ مشخص‌نکردن روش مستلزم پرسش است.

## محتوای فنی و نصب

`vendor/` فقط هستهٔ رندر و `core/lib.js` را به صورت مجزا از [Lemo-Opuscar](https://github.com/lemomo-ai/lemo-opuscar/tree/8ca0dd805e214bcc1d30714cd5b9d21cc02a454b) در نسخهٔ `8ca0dd805e214bcc1d30714cd5b9d21cc02a454b` نگه می‌دارد؛ کتابخانهٔ کامل سبک‌ها، دارایی‌ها، TTS و موسیقی همراه این نسخهٔ کوچک نیستند. موتور یک صفحهٔ HTML با `window.READY`, `window.DUR`, `window.render(t)` را فریم‌به‌فریم رندر می‌کند، نه اینکه صرفاً با یک جمله خودکار فیلم نهایی تولید کند. منابع، کپی‌رایت و مجوز کد در `vendor/LICENSE` و `vendor/LICENSES/MIT.txt` هستند؛ مجوز فونت‌ها، تصاویر، موسیقی و سایر دارایی‌های شخص ثالث را جداگانه بررسی کنید.

روی سیستم مناسب با Node.js نسخهٔ ۲۰ یا جدیدتر، ffmpeg با libx264 روی PATH، و پیش‌نیازهای سیستم Chromium، از ریشهٔ مخزن:

```sh
cd opuscar_mode/vendor
npm ci --ignore-scripts --no-audit --no-fund
node node_modules/playwright-core/cli.js install chromium-headless-shell
cd ../..
node opuscar_mode/vendor/core/render/video.mjs "$PWD/opuscar_mode/smoke" --fps 24 --workers 1 --size 480x600 --out "$PWD/opuscar_mode/smoke/local-test.mp4"
```

دانلود Chromium نیاز به دسترسی شبکهٔ لازم و کتابخانه‌های سیستم دارد؛ در محیط محدود می‌توان `PLAYWRIGHT_CHROME` را به Chromium سازگارِ نصب‌شده اشاره داد. دستور نصب بالا تنها وابستگی Node و مرورگر آزمون ساده را نصب می‌کند؛ برای کل کتابخانهٔ اصلی، نیازمندی‌های Python و دارایی‌ها را طبق اسناد نسخهٔ بالادست جداگانه فراهم کنید. `node_modules` و محیط‌های نصب‌شده در snapshot محفوظ نیستند؛ بازسازی لازم است. اسکریپت setup بالادست ممکن است clone مدیریت‌شده را reset کند؛ آن را روی مخزن کاربر اجرا نکنید.

## نتیجهٔ آزمون واقعی

در این محیط کد بالادست و وابستگی‌های Node و Python نصب و هستهٔ مجزای همین پوشه اجرا شد. خروجی `smoke/test.mp4` از `smoke/index.html` با موتور `video.mjs` ساخته و دیکود کامل و فریم میانی بررسی شد: ۲ ثانیه، ۴۸ فریم، ۲۴fps، H.264، ۴۸۰×۶۰۰، بدون صدا. تست فقط حرکت سادهٔ دایره و قوس را نشان می‌دهد، نمونهٔ کیفیت محتوای نهایی نیست. Chromium در محیط آزمایشی با رندر نرم‌افزاری SwiftShader اجرا شد؛ ۳بعدی ممکن است کند باشد. آزمون نریشن، موسیقی، فارسی یا حرکت مستقل شخصیت‌ها نبوده است. برای هر پروژهٔ واقعی صوت و تصویرسازی جداگانه لازم است؛ هویت صدای پیش‌فرض و انیمیشن مستقل شخصیت تضمین نشده‌اند.

در محیط محدود آزمون، مرورگر از بستهٔ npm `@sparticuz/chromium@158.0.0` تهیه شد؛ ffmpeg از `imageio-ffmpeg`، libnss3 و libnssutil3 از بستهٔ `chrome-aws-lambda@10.1.0` و NSPR از سورس `mozilla/nspr` در `08cfad0d78836a089efd7f1604975f2ada531c2a` ساخته شد. این وابستگی‌های موقت در Git نیستند و مراحل استاندارد بالا جایگزین آنها در محیط مناسب است.
